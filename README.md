\# Інформаційна система погодження внутрішніх документів



Курсова робота з дисципліни «Кросплатформене програмування».

Варіант №25.



\## 1. Призначення системи



Система призначена для автоматизації обліку внутрішніх документів підприємства та організації процесу їх погодження.



Основні сутності:

\- Автор;

\- Документ;

\- Рецензент;

\- Запит на погодження.



\## 2. Використані технології



\- Java 21

\- JavaFX

\- Apache Maven

\- MySQL

\- JDBC

\- Java Servlets

\- Apache Tomcat 9

\- Jackson

\- JUnit 5



\## 3. Структура проєкту



\- Сервер — серверна частина системи.

\- Клієнт — JavaFX-застосунок.

\- Дані — SQL-скрипт і CSV-файли.

\- Діаграми — діаграми проєкту.

\- Скріншоти — зображення роботи системи.



\## 4. Налаштування бази даних



1\. Запустити MySQL через XAMPP.

2\. Відкрити phpMyAdmin.

3\. Виконати SQL-скрипт Дані/database.sql.

4\. Перевірити параметри підключення у DatabaseConnection.java.



База даних: document\_approval\_db.



\## 5. Запуск сервера



1\. Відкрити серверний Maven-проєкт.

2\. Виконати Maven-команду clean package.

3\. Розгорнути server.war у Apache Tomcat 9.

4\. Запустити Tomcat.



Адреса API:

http://localhost:8080/server/api



\## 6. Запуск клієнта



1\. Відкрити клієнтський Maven-проєкт.

2\. Переконатися, що MySQL і Tomcat запущені.

3\. Виконати Maven-команду javafx:run.



\## 7. CSV-імпорт



Система підтримує імпорт документів із CSV-файлу.



Підтримується:

\- перевірка заголовка;

\- перевірка кількості полів;

\- перевірка числових значень;

\- перевірка зв'язку з автором;

\- фонове виконання імпорту;

\- відображення прогресу;

\- формування звіту про помилки.



\## 8. Інтегральний показник



Інтегральний показник пріоритетності документа:



I = 0.40 × F1 + 0.35 × F2 + 0.25 × F3



Де:

\- F1 — близькість строку;

\- F2 — критичність документа;

\- F3 — кількість залежних процесів.



Кожен фактор має значення від 0 до 100.



\## 9. Життєвий цикл погодження



DRAFT → SUBMITTED → UNDER\_REVIEW → APPROVED



\## 10. Тестування



Для серверної частини використовуються JUnit 5.



Останній підтверджений результат:

\- 29 тестів;

\- 0 помилок;

\- 0 невдалих тестів;

\- 0 пропущених тестів;

\- BUILD SUCCESS.
